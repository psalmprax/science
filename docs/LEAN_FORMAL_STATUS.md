# The Lean layer is not a verification layer (measured)

`benchmarks/formal/lean_axiom_audit.json` is generated by
`scripts/audit_lean_formal_layer.py`. These are its numbers as of the last run; the JSON is
the source of truth, and `tests/test_formal_and_applied_audits.py` fails if this file's
claims and the report disagree.

| measure | value |
|---|---|
| .lean files in the repository | 557 |
| of those, under `apedp_dyn/lean_formal/` | 366 |
| `axiom` declarations | 12,470 |
| `theorem`/`lemma` statements | 1,054 |
| `sorry` / `admit` occurrences | 345 |
| theorems proved by rewriting a *local* axiom | 0 |
| files classified `checked` (no axiom, no `sorry`) | **0** |
| files classified `axiom_injected` | 297 |
| files classified `incomplete` | 259 |
| files classified `declaration_only` | 1 |
| machine-checked fraction | **0.0** |

## What this means

Zero files are checked from Lean's own foundations. In the audited pattern a property is
declared as an `axiom` and then "proved" by rewriting with that same axiom:

```lean
axiom cube_neg (x : R) : (-x) * (-x) * (-x) = - (x * x * x)
theorem ... (x : R) : (-x) * (-x) * (-x) = - (x * x * x) := by rw [cube_neg x]
```

The theorem is true *given the axiom*, and the axiom is exactly the theorem's statement, so
nothing is established. That shape has now been removed from the tree: the generator
refuses to emit a proof that rewrites a local axiom, and the 94 theorems that did are
emitted as statements with `sorry`, so `theorems proved by rewriting a local axiom` is 0
and every rewritten file still compiles under the local Lean binary (exit 0, `sorry`
warnings only). What remains is 297 `axiom_injected` files that declare axioms without
closing that loop, and 259 `incomplete` files that admit their statements outright;
neither is evidence, because an assumed lemma is not a proof of anything it is used for.
Removing the circularity does not create a proof — it stops the file from presenting the
premise as the conclusion.

## The rule this document sets

No result in this repository may be described as **formally verified** on the strength of a
non-`checked` file. "Recorded in Lean" means a statement was transcribed into Lean syntax —
which is useful for reproducibility and for catching typos in a formula, and is all that
should be claimed for it.

## What would make it verification

1. No `axiom` local to a file: derive the property, or import the lemma from Mathlib.
2. No `sorry`/`admit` in any file a claim depends on.
3. A `lake build` transcript in CI, so the statement is checked by Lean rather than by grep.
4. `python3 scripts/audit_lean_formal_layer.py --check` passing, which today exits 1 by
   design: it requires every file to be `checked`, and none is.

Until all four hold, the honest status of this layer is **transcribed, not verified**, and
`docs/SCAFFOLD_INVENTORY.md` records it that way.
